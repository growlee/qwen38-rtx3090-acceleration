# Qwen3.8-27B-Uncensored: качество и скорость — 8 сентября 2026

На этой матрице текущий Adaptive даёт примерно на 22% больше токенов/с, чем AutoRound BF16-MTP, по взвешенной decode-метрике, но допускает два дополнительных провала coding: 24/30 вместо 26/30. Назвать это ускорением «без потерь» нельзя. Для coding из проверенных вариантов предпочтительнее AutoRound BF16-MTP как компромисс; постоянный рабочий профиль не переключался.

Набор: 30 coding, 12 reasoning RU, 12 instruction/JSON/tools, 6 retrieval; canonical SHA-256 `51bc5577046b49aa95977171a911c22756e8754ed5378234e39b47eb7e1f5c02`.

Все 180 ответов завершены; по всем 60 координатам SHA запроса совпадает между тремя вариантами. Сохранены usage, текст, отдельное reasoning, tool deltas, finish reason и время того же ответа. Новых генераций для оценки скорости или качества не было. 87 полных Python-функций проверены по одному разу в ограниченных CPU-контейнерах без сети, GPU, секретов и host mounts. ## Где изменилось качество

- AutoRound → текущий Adaptive: 2 PASS→FAIL, 0 FAIL→PASS. Оба новых провала критические coding: `code-chunked` и `code-rotate`. На строковом входе `chunked("abcd", 3)` возвращает `["abc", "d"]` вместо списков символов; `rotate("abcd", 6)` возвращает строку `"cdab"` вместо списка. Запросы требуют list-результаты. Итог −2/60 (−3,33 п.п.), coding −2/30 (−6,67 п.п.).
- GGUF → AutoRound: 2 новых coding-провала (`code-slugify-ascii`, `code-roman-to-int`) и 5 исправлений (две coding и три JSON-format задачи). Например, некорректный `IIII` принимается как 4 вместо обязательного `ValueError`.
- GGUF → текущий Adaptive: те же 2 новых coding-провала и 3 улучшения формата JSON. Поэтому больший общий PASS не означает отсутствия регрессий.
- У всех трёх совпадают шесть бесспорных ошибок RU-арифметики. Например, средняя скорость 300 км за 3 часа названа 300 км/ч вместо 100 км/ч; задача о пересечении множеств даёт 15 вместо 5. На этом режиме без thinking пригодность для рассуждений ограничена.

Критерий roadmap «нет новых критических coding/instruction-провалов относительно ориентира» не выполнен ни одним ускоренным вариантом. AutoRound рекомендуется только как измеренный компромисс, не как доказанно безошибочная или эквивалентная версия. Adaptive даёт +22,02% weighted decode; суммарное время всех ответов меньше на 13,30%, медианное парное отношение времени ответа — 0,785. Тексты/их длины различаются, поэтому это разные, явно названные меры выигрыша.

## Ограничения оценивания

Строгие оценки зафиксированы до запуска и не изменены после результатов. Два общих провала требуют оговорки:

- `reasoning-probability`: все три правильно выводят 3/10, но добавляют объяснение. Exact-check требует только `3/10`, хотя запрет объяснения в natural-language prompt не сформулирован явно. Это не ошибка вероятности.
- `instruction-nested-json`: prompt неоднозначно задаёт уровень поля `roles`; все помещают его внутрь `user`, а frozen schema требует верхний уровень. Этот FAIL не является чистым доказательством смысловой деградации.

Три дополнительных JSON-провала GGUF — правильные значения внутри Markdown fences вместо требуемого raw JSON. Отдельного «смягчённого» рейтинга задним числом нет; общие неоднозначные случаи не объясняют два новых coding-провала Adaptive.

Это 60 синтетических задач и один ответ на случай, не полноценный coding-agent benchmark, не 200k-context тест и не оценка uncensored-поведения. Original GGUF тоже квантован; нет BF16-эталона. Сравниваются конфигурации целиком: веса, runtime, template и cache-параметры не полностью одинаковы. Нельзя приписывать все различия одному только MTP или INT4 и нельзя вывести статистическую частоту ошибок из одного прогона.
